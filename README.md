# Личная CRM

Список людей, которых я знаю лично: кто это, откуда знакомы, телефон, почта и заметки о разговорах.
Идея и сценарии — в `specs/01-продуктовая-идея.md`.

## Что умеет

- Главная страница — список всех контактов по алфавиту и поиск по имени
  (регистр не важен, слова в любом порядке, «е» и «ё» не различаются)
- «Добавить контакт» — форма: имя (обязательно), кто это, откуда знакомы, телефон, почта
- Карточка контакта — все сведения и заметки; новая заметка добавляется сверху с датой и временем
  (кнопка «Добавить заметку» или Ctrl + Enter)
- Кнопка «Изменить» в карточке — поправить имя, «Кто это», «Откуда знакомы», телефон или почту;
  заметки при этом не меняются
- Кнопка «Удалить» в карточке — удалить контакт вместе с его заметками
  (после подтверждения; вернуть нельзя)
- Кнопка «Изменить» у заметки — поправить её текст прямо в карточке (сохранить — кнопкой или Ctrl + Enter,
  отменить — кнопкой или Esc); у изменённой заметки рядом с датой создания видно, когда её изменили
- Данные хранятся в базе PostgreSQL, поэтому в любом браузере видно одно и то же

## Что нужно установить

- Node.js 24
- pnpm
- Docker Desktop (в нём работает база данных)
- OpenSpec — для работы над требованиями фич: `npm install -g @fission-ai/openspec@latest`

## Настройки

Пароли и адрес базы лежат в файле `.env` (в git он не попадает). Образец — `.env.example`.
Приложение читает такие переменные:

| Переменная          | Что это                                                        |
| ------------------- | -------------------------------------------------------------- |
| `POSTGRES_USER`     | имя пользователя базы                                          |
| `POSTGRES_PASSWORD` | пароль базы                                                    |
| `POSTGRES_DB`       | название базы                                                  |
| `POSTGRES_PORT`     | порт, по умолчанию `5432`                                      |
| `DATABASE_URL`      | необязательно: полная строка подключения, заменяет всё, что выше |

## Первый запуск

Все команды выполняются в папке проекта.

```bash
pnpm install       # скачать библиотеки
pnpm db:up         # запустить базу данных в Docker
pnpm db:migrate    # создать таблицы
pnpm db:seed       # заполнить 1000 тестовыми контактами (только если база пустая)
pnpm build         # собрать приложение
pnpm start         # запустить
```

Откройте http://localhost:3000.

Чтобы остановить приложение — закройте окно, в котором оно запущено, или нажмите Ctrl + C.

## Следующие запуски

```bash
pnpm db:up
pnpm start
```

Если код менялся — перед `pnpm start` выполните `pnpm build`.

## Как устроено

- `src/app` — страницы: список (`page.tsx`), новый контакт (`contacts/new`), карточка (`contacts/[id]`),
  изменение контакта (`contacts/[id]/edit`) и серверные действия (`actions.ts`)
- `src/components` — части интерфейса
- Оформление — в одном стиле с лендингом: цвета, шрифты, размеры текста и скругления заданы в `src/app/globals.css`,
  шрифты подключены в `src/app/layout.tsx`
- `src/lib/contacts.ts` — запросы к базе; браузер к базе не обращается, всё идёт через сервер
- `src/db` — схема таблиц, подключение, применение миграций на сервере (`migrate.ts`), генератор тестовых данных
- `src/app/health/route.ts` — адрес `/health`: отвечает 200, если приложение работает и достаёт до базы
- `drizzle/` — миграции базы
- `openspec/` — требования фич (OpenSpec, тексты на русском): действующие — в `specs/`, новые и в работе — в `changes/`,
  настройки — в `config.yaml`. Команды для Claude Code — `/opsx:propose`, `/opsx:apply`, `/opsx:archive` и другие в `.claude/commands/opsx/`
- `Dockerfile` — образ приложения; его собирает GitHub Actions
- `.github/workflows/deploy.yml` и `deploy/` — автовыкатка на сервер
- `deploy/server/` — подготовка сервера: скрипт, настройки nginx и Docker, страница-заглушка

## Выкатка

Чтобы выкатить новую версию, отправьте коммит в ветку `main`:

```bash
git push
```

Дальше всё идёт само, обычно 3–5 минут:

1. GitHub Actions собирает образ приложения с тегом — SHA коммита — и кладёт его в GHCR
   (`ghcr.io/panduzverplus/personal-crm`)
2. Заходит на сервер по ключу деплоя, копирует туда `deploy/compose.yaml` и `deploy/deploy.sh` и запускает `deploy.sh`
3. `deploy.sh` применяет миграции разовым контейнером из нового образа.
   Если миграции упали — новый образ не запускается, продолжает работать старый
4. Запускает новый образ и проверяет, что https://app.chigabugadaga.ru/health отвечает 200
5. Оставляет на сервере только текущий и предыдущий образы

Ход выкатки — на вкладке Actions репозитория или командой `gh run watch`.
Зелёная галочка — новая версия на сервере. Красный крестик — выкатка упала; сама она ничего не откатывает.

Ручной откат на предыдущий образ (миграции он не отменяет):

```bash
ssh crm 'bash ~/personal-crm/deploy.sh $(cat ~/personal-crm/previous-image)'
```

Другие команды:

| Что сделать                                  | Команда                                                                                        |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| посмотреть, какой образ сейчас на сервере    | `ssh crm 'cat ~/personal-crm/current-image'`                                                   |
| посмотреть логи приложения                   | `ssh crm 'docker logs --tail 100 prod-crm-app-1'`                                              |
| заполнить пустую базу 1000 тестовыми контактами | `ssh crm 'cd ~/personal-crm && APP_IMAGE=$(cat current-image) docker compose -p prod run --rm crm-seed'` |

На сервере всё лежит в `~/personal-crm/`: `compose.yaml`, `deploy.sh`, `current-image`, `previous-image`
и `.env` с паролем базы (права 600, создаётся вручную, в git не попадает):

```
POSTGRES_USER=crm
POSTGRES_PASSWORD=<случайный пароль>
POSTGRES_DB=crm
```

База PostgreSQL работает на сервере в Docker, её данные хранятся в томе `prod_crm-db-data`.

Для выкатки в GitHub заведены секрет `DEPLOY_SSH_KEY` (приватный ключ деплоя) и переменные
`DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KNOWN_HOSTS`.

## Сервер

Сервер `153.76.175.154`, вход — `ssh crm` (пользователь `crmapp`; вход под root и по паролю закрыт).
Команды с `sudo` спрашивают пароль crmapp.

- `chigabugadaga.ru` — лендинг (пока заглушка), `app.chigabugadaga.ru` — приложение
- Один сертификат Let's Encrypt на оба домена, продлевается сам (таймер `certbot.timer`);
  http перенаправляется на https
- Docker открывает порты контейнеров только на `127.0.0.1`: наружу всё идёт через nginx.
  Логи контейнеров ограничены: до 3 файлов по 10 МБ
- Docker сам не обновляется: обновлять вручную через `sudo apt upgrade`
- Пользователь `crmapp` в группе `docker`, чтобы выкатка работала без sudo

Подготовка сервера с нуля (повторный запуск ничего не ломает):

```bash
scp -r deploy/server crm:server-setup
ssh -t crm "sudo bash ~/server-setup/setup-server.sh <почта для Let's Encrypt>"
```

Журнал последнего запуска — `/var/log/server-setup.log` на сервере.
