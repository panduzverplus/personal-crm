# Proposal

## Why

Сейчас все контакты лежат одним длинным списком, а находятся только по имени. Людей нельзя посмотреть «кучкой»: всю семью, всех с тенниса, всех аналитиков. Когда имя не вспоминается или нужен круг людей, а не один человек, приходится листать весь список. Группы раскладывают контакты по кругам общения, которые пользователь задаёт сам.

## What Changes

- Появляются группы контактов. Сразу после выкатки есть пять готовых: «Семья», «Друзья», «Знакомые», «Теннис», «Аналитики».
- Контакт может входить в несколько групп или не входить ни в одну. Существующие контакты после выкатки ни в какой группе не состоят.
- Группы назначаются галочками в форме контакта: при добавлении и в «Изменить». Там же можно создать новую группу, не уходя из формы.
- В карточке контакта появляется строка «Группы». В строке общего списка на главной группы видны мелким текстом.
- На главной под заголовком появляется ряд кнопок-фильтров: «Все» и по кнопке на группу. Нажатие оставляет только эту группу, одновременно выбрана одна. Фильтр сужает и общий список, и блок «Пора связаться». Поиск работает внутри выбранной группы.
- Ссылка возврата в карточке ведёт к тому же списку: с той же группой и тем же поисковым запросом. Выбор сохраняется, пока вы работаете с контактом.
- Появляется страница «Группы»: создать, переименовать, удалить. Названия не повторяются. При удалении группы контакты остаются, они только выходят из неё. Перед удалением приложение спрашивает подтверждение.
- Две новые таблицы в базе и миграции: одна создаёт таблицы, другая добавляет пять готовых групп.
- Подключаем Vitest: новый код пишется по TDD, а тестового фреймворка в проекте пока нет.

## Capabilities

### New Capabilities

- `contact-groups`: группы контактов — готовые и созданные пользователем, назначение групп контакту, показ в карточке и в списке, фильтр на главной, возврат из карточки к тому же списку, страница управления группами.

### Modified Capabilities

- `keep-in-touch`: блок «Пора связаться» учитывает выбранную группу. Раньше он всегда показывал всех просроченных.

## Impact

- База: таблицы `groups` и `contact_groups`, две новые миграции в `drizzle/`. Существующие таблицы не меняются, предыдущий образ приложения работает с новой схемой.
- Код:
  - данные: `src/db/schema.ts`, `src/lib/contacts.ts` (фильтр, просроченные по группе, сохранение контакта с группами), новый `src/lib/groups.ts`, `src/lib/contact-form.ts`, новый разбор параметров списка;
  - действия: `src/app/actions.ts`;
  - главная: `src/app/page.tsx`, `src/components/contact-list.tsx`, `src/components/contact-search.tsx`, `src/components/keep-in-touch.tsx`, `src/components/keep-in-touch-list.tsx`;
  - контакт: `src/components/contact-form.tsx`, страницы `src/app/contacts/new`, `src/app/contacts/[id]`, `src/app/contacts/[id]/edit`, `src/components/back-link.tsx`;
  - новая страница `src/app/groups`.
- Интерфейс: компонент галочки из shadcn/ui, написанный вручную (`@base-ui/react` уже в проекте).
- Библиотеки: Vitest в dev-зависимостях. Он указан в стеке в `CLAUDE.md`, используется только для проверок, работающее приложение его не вызывает.
- Выкатка: обычная, миграции применяются отдельным шагом до старта нового образа.
- Вне рамок:
  - e2e на Playwright и CI на PR — настроим позже, отдельно;
  - фильтр сразу по нескольким группам;
  - группы в строках блока «Пора связаться»;
  - добавление в группу сразу нескольких контактов;
  - цвета групп, вложенные группы;
  - изменение генератора тестовых данных.

## Owner Decisions

Из запроса:

- Контакт может входить сразу в несколько групп.
- Группы пользователь создаёт сам, какие хочет.
- e2e и CI настроим позже.

Из ответов на вопросы:

- Главная: фильтр по одной группе, поиск работает внутри неё.
- Назначение групп: в форме контакта, там же можно создать новую группу. В карточке группы только видны.
- Старт: пять готовых групп из примера.
- Управление: переименовать и удалить на отдельной странице «Группы». При удалении контакты остаются и только выходят из группы, перед удалением есть подтверждение.
- Блок «Пора связаться»: при выбранной группе тоже фильтруется.
- Возврат из карточки: ссылка ведёт к тому же фильтру и поиску.
- Группы в строке общего списка: показываем мелким текстом.
- Названия: две группы с одним названием завести нельзя, «Теннис» и «теннис» — одно и то же. Название обязательно, до 50 символов.

## Agent Decisions

Этого не было ни в запросе, ни в ответах. Технические решения — в `design.md`, раздел Decisions.

- Кнопки групп стоят над блоком «Пора связаться»: фильтр меняет высоту блока, и кнопки под ним прыгали бы под курсором.
- Когда список сужен, ссылка из карточки называется «Назад к списку»: подпись «Все контакты» была бы неточной.
- После удаления контакта открывается тот же список с сообщением: работа продолжается с того же места. После добавления — полный список, как раньше: в нём подсвечен новый контакт.
- Группа из формы создаётся сразу, поэтому «Отмена» оставляет пустую группу: так у группы один путь создания и проверки названия.
- Название, вписанное без нажатия «Создать», группу не создаёт, предупреждения нет: создание группы — отдельное действие, контакт сохраняется своей кнопкой.
- «е» и «ё» в названиях считаются одной буквой: так уже работает поиск.
- Ссылка на страницу групп — «Настроить группы» в конце ряда кнопок: в шапке приложения нет меню, а настраивают группы рядом с фильтром.
- На кнопках групп нет числа контактов: ряд остаётся компактным. Число есть на странице «Группы» и в окне удаления.
- Пустые группы видны в ряду кнопок: иначе новая группа не появилась бы на главной до первого контакта.
- Поиск не сужает блок даже при выбранной группе: при поиске блок работает как раньше и зависит только от группы.
- Смена группы сворачивает раскрытый блок: в другой группе другие люди.
- Ссылка с удалённой группой открывает «Все» без ошибки: старая ссылка не должна ломать страницу.
- Группа, удалённая в другой вкладке, пропускается при сохранении контакта: из-за этой отметки не должны теряться остальные правки.
- Разделитель групп в строках — « · », как в строке частоты общения.
